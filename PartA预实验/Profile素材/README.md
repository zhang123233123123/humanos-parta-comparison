# Part A 预实验：原正式实验 Profile

已从原始服务器备份提取 **18 人、两个阶段共 36 份首次提交 Profile**，并与既有正式实验存档逐项核对一致。

## 先看哪里

- `Profile总览.html`：18 人的首次填写汇总与逐人详情。
- `正式实验18人_首次Profile.csv` / `.json`：每人一份，默认预实验输入；`逐人Profile/` 可单独取用。
- `正式实验36份_阶段对照.csv`：两阶段首次提交的对照。
- `正式实验36份_阶段记录.json`：保留进入时、首次提交、备份中的最终值及事件出处；是 Profile 字段投影，不是完整用户表。
- `来源与核验.json`：源文件哈希、字段范围、数量与只读核验。
- `队列筛选记录.json`：保留全部 30 个分配账号在两系统的纳入状态，不暴露登录账号。

## 取值规则

沿用此前原正式实验的 18 人队列：A01–A09、B16–B24。B16 对应访谈 B1，B20 对应 B5，B24 对应 B9；旧数字编号 P16/P20/P24 等只是映射别名，不增加人数。

每个阶段取第一次 `setup_submitted` 之前最近的 `profile_updated.after`，不使用未经提交的出厂用户表，也不把第二阶段预填当作独立用户。第一阶段首次提交作为默认预试输入，避免把后续使用后的改动混为初始偏好；第二阶段及备份最终值供另外核对，未自动覆盖。

本次保留全部 18 人，不套用旧分析中对个别编号的排除；也不使用后续合成六人或调整评分数据。备份另有 A14、B30 的提交记录，但不在既有正式队列中，记录于筛选表，未擅自增加正式人数。此处的“首次提交”指数据库记录，不证明所有字段都被手动修改。

## 与新版五维 Profile 的对应

|新版维度|旧数据|覆盖边界|
|---|---|---|
|典型工作时段|早／午／晚典型精力|可作历史自报信息，不等于直接测得时段偏好；条件与例外未完整采集|
|任务顺序|无对应结构化题|不把切换偏好或跨天分配当作先难后易；自由文字只保留，不自动推断|
|工作块|专注分钟数|有时长，没有完整的自然停点／适用例外信息|
|休息|休息分钟数|有时长，休息形式与触发方式不完整|
|集中或交替推进|任务切换偏好|部分覆盖，仍需按新版题意确认；空值不改成某种偏好|

第一阶段有 3 人的早午晚精力与默认 5/4/3 相同，2 人的切换字段为空。相同取值只作来源提示，不代表不认真，也不能据此删除人或补造答案。专注与休息默认取值一致的字段也逐人保留标记。

## 用于 Part A 时

这些 Profile 可以作为历史输入做离线计划生成预试，**不代表新研究的参与者已经填写或确认过新版五维问卷**。正式招募后仍需本人重新确认。

按用户新增要求，`first_day_context` 单独保存首次设置首日的可用时间和固定事项，供四条件共享使用。历史任务与阶段目标不并入新任务场景。每日状态和旧评分不混入 Profile。对新任务的难度评分尚未收集，不从历史任务推断，也不从其他人借用。

导出的身份、学习方式、失败经历等扩展信息仍保留原文，供核查；哪些字段实际放入 HumanOS 条件 prompt 需单独冻结，不能因本包有更多字段就自动全部输入模型。

本包仅本地保存去掉登录身份后的历史研究资料；未调用模型、未上传服务器、未修改原始数据库或已有任务素材。CSV/JSON 是材料格式，非现有服务器导入接口格式。

## 可复现性

执行 `python3 PartA预实验/Profile素材/提取Profile.py` 可从本地备份重建。需保留来源与核验文件列出的备份及编号映射。
